# ربات آربیتراژ ارز دیجیتال

ربات آربیتراژ بین صرافی‌ها (Cross-Exchange Spot Arbitrage) به زبان پایتون.

## آربیتراژ چیه؟

وقتی قیمت یک ارز در دو صرافی با هم فرق داشته باشه، از صرافی ارزان‌تر می‌خریم و در صرافی گران‌تر می‌فروشیم. اختلاف قیمت منهای کارمزد، سود ماست.

## کدوم ارز مناسب آربیتراژه؟

| ارز | نقدینگی | اختلاف قیمت بین صرافی‌ها | مناسب برای |
|---|---|---|---|
| BTC, ETH | خیلی زیاد | خیلی کم (~۰.۱٪) | بی‌خطرترین ولی سود کم |
| SOL, XRP, DOGE, ADA, AVAX | زیاد | متوسط | **بهترین تعادل** |
| Stablecoin (USDT/USDC) | زیاد | تقریبا صفر | اصلا مناسب نیست |
| آلتکوین‌های کوچک | کم | زیاد | اسپرد هست ولی پرشدن سفارش معلوم نیست |

## نکته مهم (واقعیت بازار)

بین صرافی‌های بزرگ مثل بایننس و بای‌بیت، اختلاف قیمت معمولا **زیر ۰.۲٪** است و چون کارمزد تیکر هر صرافی ~۰.۱٪ است (دو طرف = ۰.۲٪)، با کارمزد استاندارد سودی نمی‌مونه. اینجا دو راه دارید:

1. **کارمزد کمتر**: با توکن صرافی (مثل BNB برای بایننس) یا VIP سطح بالاتر، کارمزد را به ~۰.۰۷۵٪ برسانید.
2. **صرافی‌های کوچک‌تر**: بین صرافی‌های کوچک‌تر (MEXC، Bitget، Gate) اختلاف قیمت بزرگ‌تره ولی نقدینگی کمتر.

ربات با `MIN_PROFIT_PERCENT` فقط فرصت‌هایی را اجرا می‌کند که بعد از کارمزد سودده باشند.

## نصب

```powershell
cd arbitrage-bot
python -m pip install --index-url https://pypi.org/simple -r requirements.txt
```

> اگر pip شما به میرور ایران (pypi.ir) وصل است و پکیج پیدا نمی‌کند، با `--index-url https://pypi.org/simple` نصب کنید.

## اجرا

```powershell
python main.py                # اجرای دائم + داشبورد وب (پیش‌فرض)
python main.py --headless     # اجرای دائم بدون داشبورد
python main.py --once         # یک بار اسکن بازار و خروج
python main.py --report       # اسکن و ساخت گزارش استاتیک در پوشه report/ (بدون معامله)
python main.py --selftest     # تست کامل خرید+فروش با داده مصنوعی
python main.py --port 9000    # تغییر پورت داشبورد
```

## داشبورد وب (در مرورگر)

وقتی `python main.py` اجرا شود، ربات در مرورگر قابل مشاهده است:

```
http://127.0.0.1:8080
```

داشبورد شامل: وضعیت ربات، آخرین اسکن، سود تحقق‌یافته، تعداد معاملات، فرصت‌های اخیر، اسپرد زنده هر ارز، تاریخچه معاملات و بیلنس تستی. هر ۳ ثانیه خودکار به‌روز می‌شود.

داده‌ها (بیلنس، معاملات، سود) در `state.json` ذخیره می‌شود و **با ری‌استارت ربات از بین نمی‌رود**. معاملات در `trades.csv` و لاگ در `arbitrage.log` ثبت می‌شوند.

## تنظیمات (config.py)

| تنظیم | توضیح |
|---|---|
| `EXCHANGES` | لیست صرافی‌ها (پیش‌فرض: binance, bybit) |
| `SYMBOLS` | جفت‌ارزهایی که اسکن می‌شوند |
| `TRADE_SIZE_USDT` | حجم هر معامله به دلار |
| `MIN_PROFIT_PERCENT` | حداقل سود درصدی بعد از کارمزد (پیش‌فرض ۰.۱٪) |
| `SCAN_INTERVAL_SECONDS` | فاصله بین اسکن‌ها |
| `PAPER_TRADING` | `True` = حالت تستی، `False` = معامله واقعی |
| `USE_TESTNET` | در حالت واقعی، سفارش‌ها به testnet صرافی می‌روند |
| `DASHBOARD_PORT` | پورت داشبورد وب (پیش‌فرض ۸۰۸۰) |
| `MIN_PROFIT_PERCENT` | حداقل سود ٪ (پیش‌فرض ۰.۰۵٪ = نیم در هزار) |

## حالت‌ها

### ۱. Paper Trading (پیش‌فرض، بدون API Key)
- داده قیمت از **بازار واقعی** (public API) خوانده می‌شود.
- خرید/فروش فقط شبیه‌سازی می‌شود (`PAPER_START_USDT` و `PAPER_START_BASE` بیلنس اولیه هر صرافی).
- بیلنس دو طرف هر صرافی پر است؛ یعنی مثل روش «سرمایه از قبل در هر دو صرافی» عمل می‌کند.

### ۲. Testnet (پول تستی)
1. در [testnet.binance.vision](https://testnet.binance.vision) یا [testnet.bybit.com](https://testnet.bybit.com) حساب بسازید (پول تستی رایگان می‌دهند).
2. API Key بسازید و در `config.py` پر کنید (یا از متغیر محیطی `BINANCE_API_KEY` و `BINANCE_SECRET`).
3. `PAPER_TRADING = False` و `USE_TESTNET = True` بگذارید.

### ۳. معامله واقعی (با احتیاط!)
1. `PAPER_TRADING = False` و `USE_TESTNET = False`.
2. کلیدهای API را فقط با دسترسی **Spot trading** بسازید (دسترسی برداشت/Withdraw را فعال نکنید).
3. کلیدها را در متغیر محیطی بگذارید تا در git ذخیره نشوند.
4. اول با `TRADE_SIZE_USDT` خیلی کوچک (مثلا ۱۰) تست کنید.

> **خطر مهم**: برای فروش در صرافی دوم باید ارز را از صرافی اول به آنجا **انتقال** دهید که چند دقیقه طول می‌کشد و قیمت ممکن است جابه‌جا شود. روش عملی این است که در هر دو صرافی هم USDT و هم ارز نگه دارید (همان که حالت Paper شبیه‌سازی می‌کند). آربیتراژ بین صرافی‌ها یک بازی سریع است؛ هر چه اسکن و اجرا سریع‌تر باشد سود بیشتر است.

## داشبورد آنلاین با GitHub Actions + GitHub Pages

یک مخزن روی گیت‌هاب بگیرید، فایل‌ها را push کنید تا workflow ها خودکار شروع شوند:

| فایل | کار |
|---|---|
| `.github/workflows/ci.yml` | با هر push/PR، `--selftest` اجرا می‌شود (چک سلامت ربات) |
| `.github/workflows/pages.yml` | هر ساعت یک‌بار بازار را اسکن می‌کند و داشبورد استاتیک را روی GitHub Pages منتشر می‌کند (همچنین روی هر push و با دکمه Run workflow) |

### راه‌اندازی Pages

1. مخزن را بسازید و push کنید:
   ```bash
   git init
   git add .
   git commit -m "arbitrage bot"
   git branch -M main
   gh repo create arbitrage-bot --public --source=. --push
   ```
2. در تنظیمات مخزن: `Settings → Pages → Source: GitHub Actions` انتخاب کنید.
3. از تب **Actions** روی `Deploy Dashboard to Pages` و دکمه **Run workflow** بزنید (یا push کنید).
4. آدرس داشبورد عمومی شما می‌شود: `https://<username>.github.io/arbitrage-bot/`

### محدودیت مهم (راست بگوییم)

- GitHub Actions یک ماشین همیشه‌روشن نیست. هر اجرا محدود است؛ بنابراین **خود ربات را نمی‌توان روی Actions اجرا کرد** (معامله‌ی ۲۴/۷ نه).
- کاری که Actions می‌کند: هر ساعت بازار را اسکن می‌کند و یک عکس فوری از وضعیت (اسپردها، فرصت‌ها، سود) روی وب منتشر می‌کند. داشبورد شما در اینترنت دیده می‌شود ولی معامله نمی‌کند.
- برای اجرای ۲۴/۷ ربات روی همان کامپیوتر خودتان (`python main.py`) یا یک سرور (VPS) است.
- در یک مخزن **عمومی**، هرگز API Key را کامیت نکنید. workflow ها در CI به کلیدها دسترسی ندارند (فقط بازار عمومی را اسکن می‌کنند). اگر خواستید CI هم معامله کند، کلیدها را به‌عنوان Repository Secret اضافه کنید ولی این کار توصیه نمی‌شود.

## راهنمای کامل: صفر تا صد ربات

### ۱) آربیتراژ چیست؟
قیمت یک ارز در دو صرافی کمی متفاوت است. از صرافی ارزان می‌خریم و در صرافی گران می‌فروشیم. سود = اختلاف قیمت منهای کارمزد دو طرف.

### ۲) ربات چه می‌کند؟
این ۵ کار را در یک حلقه بی‌پایان انجام می‌دهد:
1. **اتصال** به ۱۸ صرافی (فایل `exchange_manager.py`).
2. **اسکن** قیمت همه ۱۲ ارز از همه صرافی‌ها با عمق بازار (فایل `scanner.py`).
3. **محاسبه** سود بعد از کارمزد برای همه جفت‌صرافی‌ها.
4. **اگر سود از آستانه** (`MIN_PROFIT_PERCENT`) بیشتر بود، در صرافی ارزان **خرید** و در صرافی گران **فروش** می‌کند (فایل `trader.py`).
5. **ثبت** همه‌چیز در `state.json` و نمایش در داشبورد.

### ۳) پول تستی کجا و چطور؟
- به محض اجرای `python main.py` حالت **Paper Trading** فعال است (پیش‌فرض). هر صرافی ۱۰,۰۰۰ دلار پول مجازی + ۱۰۰ واحد از هر ارز دارد.
- قیمت‌ها از **بازار واقعی** خوانده می‌شوند، ولی خرید/فروش فقط روی کاغذ ثبت می‌شود. هیچ پولی جابه‌جا نمی‌شود.
- این بهترین راه تست است چون آمار واقعی می‌دهد ولی خطری ندارد.

### ۴) خودکار بودن
ربات با `run_forever` هر ۵ ثانیه اسکن و در صورت فرصت، خودش معامله می‌کند. هیچ دخالت دستی لازم نیست. `trades.csv` و داشبورد، تاریخچه را نشان می‌دهند.

### ۵) مراحل رفتن به پول واقعی
1. چند هفته در حالت Paper بگذارید و با `--selftest` تست کنید.
2. یک حساب کوچک در صرافی دلخواه (مثلا Bitget یا Bybit) بسازید.
3. API Key با دسترسی **فقط Spot** (بدون Withdraw) بسازید و در متغیر محیطی بگذارید.
4. `PAPER_TRADING = False`، `USE_TESTNET = True` برای تست؛ بعد `USE_TESTNET = False` برای واقعی.
5. اول با `TRADE_SIZE_USDT` خیلی کوچک شروع کنید.


## نکته درباره صرافی‌ها

پیش‌فرض ۱۸ صرافی است که از این شبکه تست شده‌اند و جواب می‌دهند:

`binance, bybit, okx, bitget, mexc, gate, bingx, lbank, coinex, phemex, whitebit, htx, kraken, coinbase, poloniex, cryptocom, bitrue, kucoin`

- اسکن بین همه صرافی‌ها به صورت **موازی** انجام می‌شود (هر اسکن چند ثانیه).
- اگر یک صرافی در دسترس نباشد، خودکار رد می‌شود و بقیه کار می‌کنند.
- هر صرافی که می‌خواهید بردارید/اضافه کنید را در `EXCHANGES` در config.py تغییر دهید. کتابخانه ccxt حدود ۱۰۰ صرافی را پشتیبانی می‌کند.
- مطمئن شوید نام صرافی در `TAKER_FEES` باشد (کارمزد تیکر اسپات را تقریبی گذاشته‌ام؛ برای دقت بیشتر از صفحه کارمزد خود صرافی چک کنید و در config.py اصلاح کنید).
- `kucoin` فقط عمق ۲۰ یا ۱۰۰ می‌دهد؛ ربات خودش آن را مدیریت می‌کند.
- بایننس برای کاربران ایران محدودیت IP دارد؛ اگر به آن دسترسی ندارید از `EXCHANGES` حذفش کنید.
